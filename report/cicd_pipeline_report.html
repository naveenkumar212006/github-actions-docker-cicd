1 Abstract

Modern cloud computing services (such as AWS, Azure, and GCP) frequently incur recurring operational fees and complex credential barriers, making them inaccessible for rapid prototyping, local staging, academic verification, and cost-constrained deployments. This project architects and implements a production-grade, zero-cost Continuous Integration and Continuous Deployment (CI/CD) pipeline. By unifying GitHub Actions for cloud-hosted testing and automated container builds, Docker Hub as a free public artifact registry, and a local Minikube cluster as the deployment target, the system demonstrates an end-to-end delivery cycle without external cloud infrastructure costs.

💡 Core Architecture Highlight
Developers commit code locally → GitHub Actions automatically triggers multi-version linting and unit tests → Docker Buildx builds a secure, non-root Alpine container image → Image is published to Docker Hub → Local Minikube pulls and deploys the container with zero-downtime rolling updates and active health probes.
2 Introduction

Continuous Integration and Continuous Deployment represents the foundation of modern DevOps methodologies, enforcing code consistency, automated verification, and rapid release cadences. However, organizations and developers often face steep friction when establishing deployment targets due to cloud vendor lock-in, infrastructure subscription requirements, and security token complexities.

The primary objective of this project is to eliminate cloud dependency while preserving strict industry best practices: automated quality gates, deterministic build caching, container immutability, container security via unprivileged runtime users, and Kubernetes-native liveness and readiness monitoring. The implementation features a modular Node.js microservice equipped with real-time diagnostic telemetry, container health probes, and an interactive web dashboard.

4 Steps Involved in Building the Project
Step 1: Microservice Development & In-Memory Test Harness Application Layer

Engineered an event-driven web application (src/app.js, src/server.js) delivering an interactive UI, memory metrics, and health endpoints (/health, /api/info). Constructed an in-memory test suite (tests/app.test.js) using Node’s native node:test and node:assert runner, executing all 7 unit tests in under 3 milliseconds without socket port conflicts.

Step 2: Optimized Containerization & Docker Compose Setup Docker Engine

Authored an Alpine-based Dockerfile implementing defense-in-depth security: non-root user execution (USER node), layer caching for package manifests, and an internal HEALTHCHECK instruction. Configured docker-compose.yml mapping port 3000:3000 with health monitoring and restart policies for local testing.

Step 3: GitHub Actions CI/CD Pipeline Configuration Cloud Automation

Configured .github/workflows/ci-cd.yml across two distinct stages: (1) Test Stage: spins up a Node.js matrix (20.x, 22.x) to execute syntax linting and tests; (2) Build & Push Stage: initializes QEMU and Docker Buildx, authenticates with Docker Hub via repository secrets (DOCKERHUB_USERNAME, DOCKERHUB_TOKEN), and pushes multi-architecture image layers with GitHub Actions cache (type=gha).

Step 4: Kubernetes Manifests & Local Minikube Deployment Kubernetes Orchestration

Authored declarative manifests (k8s/deployment.yaml, k8s/service.yaml). Configured 2 pod replicas, rolling update strategy (maxSurge: 1, maxUnavailable: 0), resource quotas, and HTTP liveness/readiness probes targeting /health. Automated deployment using scripts/deploy-minikube.sh with Minikube service exposure on NodePort 30080.

5 Conclusion

This project proves that robust, enterprise-grade Continuous Integration and Continuous Deployment workflows can be established without cloud expenses. By leveraging GitHub Actions' cloud-hosted runners for testing and container compilation alongside free public registries (Docker Hub) and local container runtimes (Minikube / Docker), developers gain full visibility into automated delivery pipelines.

The pipeline achieved zero build errors, zero runtime vulnerabilities, sub-second test execution, and zero-downtime rolling updates verified through Kubernetes readiness checks. This architecture serves as an optimal blueprint for student projects, DevOps portfolio demonstrations, and local development environments seeking industry-standard practices without infrastructure billing.
